# 2026-07-22

## 风扇控制功能（设置弹窗）
- 需求：设置弹窗加"左风扇满速/右风扇满速"两个复选框，勾选满速、取消恢复系统默认；以当前电脑兼容为验收标准。
- 本机：MacBookPro18,1（MacBook Pro 14" M1 Pro），双风扇，F0=左 F1=右，最大转速 4296/4744 RPM。
- 方案（参考 qi-xmu/mac-fan-control 文档）：Apple Silicon 用 SMC key 控制——`F%dMd`=1 强制 + `F%dTg`=最大转速 满速；`F%dMd`=0 恢复自动。读无需权限，**写必须 root**。
- 实现：新增 `FanControl.swift`（SMC 读写 + 风扇 API + osascript 提权 + `--fanctl info|set|auto` CLI）；`main.swift` 在启动 NSApplication 前拦截 `--fanctl`；`SettingsWindowController` 加"风扇"区块（双风扇=左/右两框、单风扇=一框、无风扇隐藏，复选框状态=SMC 真实模式位，打开面板时同步，另显示实时转速）；`build.sh` 加源文件与 `-framework IOKit`。
- 提权方式：勾选时 osascript `do shell script ... with administrator privileges`（系统授权弹窗，支持 Touch ID）以 root 重调自身 `--fanctl set/auto`。取消授权静默还原复选框。
- **改进（同日）**：用户反馈每次都要手动输入密码太烦。已从 osascript 改为 Security 框架 `AuthorizationCreate` + `AuthorizationCopyRights` + `AuthorizationExecuteWithPrivileges`，缓存 AuthorizationRef。首次勾选弹授权框一次，同 App 会话内后续复用不再弹窗。Touch ID 支持与否取决于 App 是否有正式签名。
- **第二次改进（同日）**：`AuthorizationExecuteWithPrivileges` 在新 macOS SDK 中 dlsym 找不到符号，风扇完全无法控制。改为 sudoers 方案：首次操作通过 osascript 一次性写入 `/etc/sudoers.d/clipboardhistory`（`%admin ALL=(ALL) NOPASSWD: <binpath> --fanctl *`），之后所有风扇操作通过 `sudo -n` 免密执行，不再弹窗。依赖零废弃 API，兼容所有 macOS 版本。App 路径变化时自动重装规则。
- **第三次修复（同日）**：实际仍每次弹窗。根因：`/etc/sudoers.d/` 文件权限 0440 root:wheel，当前用户不在 wheel 组 → `FileManager.fileExists` 和 `String(contentsOfFile:)` 永远失败 → `sudoersNeedsInstall` 永远返回 true → 每次都重装。修复：用 UserDefaults 缓存安装成功的二进制路径；追加前置探针（`sudo -n <bin> --fanctl info`）检测旧版本遗留规则是否仍有效，避免不必要的重装弹窗。此外，`sudo -n` 失败时自动清缓存并重试一次（处理路径过期）。
- 关键坑：Swift 内嵌结构按 size 而非 stride 排布，`SMCKeyData.KeyInfo` 需显式 3 字节补齐到 12，否则整个 SMCKeyData_t 不是 C 的 80 字节布局（已加运行时 stride==80 自检）。
- 已验证：编译通过；`--fanctl info` 读取正常；非 root 写入被 kIOReturnNotPermitted 拒绝且报错干净。提权写入路径待用户在 UI 勾选验收（会弹授权框）。
- ponytail 注释：无 Md key 机型的 F%dMn 回退路径未真机验证；睡眠/重启后系统可能自动恢复，不做持久化（复选框即硬件真实状态）。
