# 2026-09-13

## 风扇提速比例从固定 80% 改为可调百分比

需求：把写死的 `FanControl.boostRatio = 0.8` 改为设置面板里可手动拖动的百分比。

改动（3 个文件，`bash build.sh` 通过，`--fanctl info` 实测正常）：
- `FeatureSettings.swift`：新增 `fanBoostPercentKey` / `fanBoostPercentDefault=80` / `Min=20` / `Max=100`；`fanBoostPercent` getter 未设置时回退 80（不依赖 register(defaults:) 顺序），`setFanBoostPercent` 取整+钳制后调用 `FanSupervisor.shared.boostPercentDidChange()`；`fanBoostRatio` 供 FanControl 使用；`resetToDefaults` 一起复位为 80。
- `FanControl.swift`：
  - `boostRatio` 由 `let` 常量改为计算属性 `FeatureSettings.fanBoostRatio`。
  - **关键坑**：`setTargetRPM` 在 root 子进程里运行（sudo 会把 HOME/UserDefaults 域切到 root），读不到当前用户的百分比设置 → 给 `Ftst` 解锁后「其余风扇兜底目标」加 `fallbackRatio` 显式入参；`apply()` 在**本进程**取好 percent，CLI 变成 `--fanctl set <fan> <rpm> [percent]`（第 4 个参数可选，缺省回退读设置）。sudoers 规则 `--fanctl *` 通配无影响。
  - `FanSupervisor`：新增 `boostPercentDidChange()`（模式位仍是 Mode 1/2 时 refresh() 判定「没丢失」不会补发，必须显式重下）与 `finishApplyQueue()`；`awaitingReapply` 标志解决「下发在飞时用户又拖了滑块 → 旧比例覆盖新比例」。
  - CLI `info` 输出的「80% 目标」改为动态百分比。
- `SettingsWindowController.swift`：风扇区新增「提速目标转速」滑块（20~100，宽度 96 的 label 行，面板高度 560→600）；拖动中只刷新读数、**松手才落库并重新下发**（避免逐像素触发一次提权）；复选框标题与提示文案随百分比刷新。
- 顺带修一个自己引入的竞态：`onReset` 改为**先**清 `FanSupervisor.setBoosted(_,false)` **再** `FeatureSettings.resetToDefaults()`——否则恢复默认会把百分比改回 80% 并触发重下发，与随后的 `auto` 命令颠倒，可能出现「未勾选但仍是手动」。
