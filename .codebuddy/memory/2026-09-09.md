# 2026-09-09

## 修复：开启风扇提速后锁屏黑屏无法休眠

现象：勾了风扇高速（SMC 手动 80%）后，锁屏黑屏时风扇一直高速转，机器停在黑屏再也进不了休眠；不开风扇时黑屏后会正常休眠。

根因判断（关键认知，写进长期记忆）：**风扇处于 SMC 手动/强制模式本身就会阻止 macOS 进入睡眠**，于是形成死锁——`FanSupervisor` 原本只在 `willSleepNotification` 时交还控制权，而 `willSleep` 正因为风扇被强制而永远不来 → 风扇转着 → 睡不着。次要嫌疑（每 5s 的巡检/sudo 补发后台唤醒）已一并规避。

修复（`ClipboardHistory/Sources/FanControl.swift` 的 `FanSupervisor`）：
- 新增挂起原因 `.displayOff` / `.screenLocked`；新增事件源：`NSWorkspace.screensDidSleep/Wake`、`sessionDidBecomeActive`、分布式通知 `com.apple.screenIsLocked/Unlocked`（注意 `CGSSessionScreenIsLocked` 已从 `CGSessionCopyCurrentDictionary()` 移除，锁屏只能靠通知 + `sessionDidBecomeActive` 兜底）。
- `shouldStayReleased()` 扩展为「合盖 || 主显示器 asleep(`CGDisplayIsAsleep(CGMainDisplayID()) != 0`) || 已锁屏」，防止巡检在黑屏期间立刻恢复把死锁又造出来。
- 巡检间隔按状态自适应：正常 5s，挂起期间 15s（新增 `restartTimer()`），减少后台唤醒。
- `didWake` 改为走 `resumeIfPossible()` + 2s 后重试（唤醒瞬间屏幕可能还没点亮）。
- UI：开关文案改为「合盖 / 锁屏 / 睡眠时恢复系统控制」，状态后缀按四种原因分别显示（`SettingsWindowController.swift`）；`FeatureSettings` 注释同步。

行为：黑屏/锁屏即交还风扇控制权 → 系统能正常休眠；亮屏/解锁/唤醒后自动恢复提速。仍受开关 `fanReleaseWhenClosed`（默认开）控制。编译通过（arm64，bash build.sh）。

### 追加：另外两类「人不在」场景（同日实现）

- 屏保运行：监听分布式通知 `com.apple.screensaver.didstart`（挂起，reason `.screenSaver`）与 `didstop`/`willstop`（恢复）；系统不保证发 didstop，故 `screensDidWake` 里兜底清标志。
- 会话不在控制台：`shouldStayReleased()` 增加 `isSessionOffConsole()`，用 `CGSessionCopyCurrentDictionary()[kCGSessionOnConsoleKey] == false` 权威查询（无状态位、不会漏通知），覆盖快速用户切换 / 登录窗口 / 远程桌面接管（这些场景不发 screenIsLocked）。查不到时按「在控制台」处理，不误伤。
- UI 状态后缀新增「屏保中」「会话已切走」。编译通过。
