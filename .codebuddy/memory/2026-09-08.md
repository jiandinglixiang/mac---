# 2026-09-08

## 合盖/睡眠后风扇仍高速转动：新增「合盖即交还系统控制」

### 原因
- SMC 的手动模式（F%dMd=1 + F%dTg=80%）**不会随睡眠/合盖自动清除**，一次性写入后 SMC 由常供电源轨维持，风扇按目标转速一路转到唤醒。
- 更常见的情形：合盖但机器没睡（外接显示器的合盖模式，或存在 NoIdleSleepAssertion），`FanSupervisor` 每 5s 的巡检仍在持续补发手动模式 → 风扇恒 80%。
- 旧代码在 `willSleep` 只 stop 定时器，没有真正交还控制权。

### 实现
- `FanControl.isLidClosed()`：优先读 IOPMrootDomain 的 `AppleClamshellState`（实测本机存在，开盖=No），回退 SMC `MSLD`；都不可用返回 nil（台式机）。CLI 加 `--fanctl lid` 便于自检。
- `FanControl.releaseAllAndWait(_:timeout:)` / `releaseAll(_:)`：串行队列 `fan.release` 上逐个发 `--fanctl auto`，阻塞版用于 willSleep（超时 5s，阻塞主线程是有意为之，通知处理完系统才睡），异步版用于巡检。
- `FanSupervisor`：新增 `isSuspended` / `suspend(reason:wait:)` / `resumeIfPossible()` / `shouldStayReleased()`。willSleep 同步释放；didWake 清除挂起并 refresh（盖子仍合则继续挂起）；巡检每轮查盖子，合盖挂起、开盖恢复；补发队列 `applyNext` 被挂起时立即停手避免与释放命令打架；已挂起时收到 willSleep 会再发一次（setAuto 幂等，防异步释放未完成就睡）。
- 设置开关 `FeatureSettings.fanReleaseWhenClosed`（默认开，未设过按 true），UI 在风扇区块加「合盖 / 睡眠时恢复系统控制」；挂起时状态标签显示「（合盖/睡眠中，已交还系统控制）」。

### 验证
`bash build.sh` 编译通过；`--fanctl lid` 输出「盖子: 打开」。真机合盖测试待用户做。注意用户当前运行的是 `/Applications/剪贴板历史.app`，需替换后重启才生效（sudoers 绑定该路径，同路径覆盖不影响免密）。

### 复核修复（用户重启后确认有效，再次通读）
1. **只释放勾选风扇的隐患**：M3/M4 走 Ftst 解锁时 `setTargetRPM` 会把未勾选风扇一并设手动 80%；原 `suspend` 只释放 `boosted`，未勾选风扇会一直手动、且 `setAuto` 的 `anyFanForced` 检查会因此拒绝复位 Ftst。改为释放**全部**风扇（`0..<fanCount`，读不到时回退 boosted）。
2. **并发竞态**：挂起瞬间若有补发命令在飞，可能把某风扇又写成手动。挂起分支每轮检查 `isForced==true` 的 boosted 风扇并再次 `releaseAll`（幂等自愈）。
3. `suspendReason` 改为 `private(set)` 暴露，状态标签按 `.lid/.systemSleep` 显示「合盖中/睡眠中」。
