# 2026-09-21

## 修复：历史窗口图片不显示、也粘贴不出内容（9-14 性能重构引入的回归）

**现象**：只有文字/链接/文件正常，图片卡片空白且点粘贴无内容（其他类型无此问题）。

**根因**（`ClipboardItem.imageData` 读取链路断路）：
- 重构后图片元数据与字节分离：新抓取条目内存持 `inMemoryImageData`，`HistoryStore.save()` 落盘后再调 `releaseInMemoryImageData()` 释放内存。
- 但 `imageDataLoader` 当时是 `((String) -> Data?)?`，**只有 `HistoryStore.makeItem`（从磁盘恢复的历史条目）会注入**；新抓取条目从没 loader。
- 于是释放内存那刻起：`imageData` 永久返回 nil → 缩略图为空、`copyToClipboard` 的 `NSImage(data:)` 拿不到数据 → 写不进剪贴板。
- 磁盘数据一直是好的（11 个 `.dat` 全是可解码 TIFF，`images/` 29MB）；因为 app 自 9/15 一直没重启，历史里全是「本会话抓取」的对象，所以一条图片都显示不出来（重启一次能临时恢复，这也是旧版注入 loader 的路径）。

**修复**：
1. `ClipboardItem.imageDataLoader` 改为非可选 + 默认实现 `{ HistoryStore.shared.imageData(fileName: $0) }`；`HistoryStore.makeItem` 里那处注入删除（单一来源）。
2. `HistoryStore.write` 返回「确认写成功的文件名集合」，`save` 只对写成功的图片释放内存副本（失败则保留数据、下次 save 重试）；跳过写盘的 guard 改为 `ids != lastWrittenIDs || !pendingImages.isEmpty`，让失败可重试。
3. 卡片缩略图拿不到数据时退回显示体积文本（不再整块空白）。

**验证方式（可复现）**：写隔离沙箱（`/tmp/ch-imgtest`）——复制 `ClipboardItem/ThumbnailCache/HistoryStore` 源码，用 sed 把 `HistoryStore` 的 `base` 指向临时目录，配一个 `main.swift` 测「抓取→save→释放内存→读图/缩略图/NSImage→load 重启恢复→二次 save」+ 文本/链接/文件三类恢复。修复前失败 6 项、修复后全绿（缩略图 240x160 < 360）。沙箱已清理。

**审计结论（其他类型）**：文本/链接/文件的数据都直接挂在对象上（`textContent`/`urlString`/`fileURLs`），不走 loader，因此不受影响；卡片的 NSWorkspace 图标、粘贴写 URL 路径均正常。已知遗留（非本次回归，未改）：图片去重仍按 `imageByteCount` 比较（同尺寸不同图会误判重复）；剪贴板 TIFF 原样落盘（4.4MB/张，11 张 29MB），如需省盘需在后台转 PNG。
