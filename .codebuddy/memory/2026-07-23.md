# 2026-07-23

## Bug 修复（第二轮）：风扇复选框深度重写

### 背景
上一轮修复把 `show()` 改成不读 SMC（只刷新 RPM），虽然窗口重开状态保持了，但复选框显示的是 UI 残留状态，与硬件真实状态脱节——SMC Mode 3 也会被误判为强制模式。

### 根因分析（查阅三方开源研究）
- **agoodkind/macos-smc-fan** (MIT)：首次公开 Apple Silicon M1-M5 风扇解锁机制
- **leaperone/smctl**：SMC 逆向研究文档
- **qi-xmu/mac-fan-control**：Apple Silicon 双模式控制文档

关键发现：`F%dMd` 有 4 种模式：
- 0 = Auto（自动）
- 1 = Manual（用户强制）  
- 2 = Legacy forced（仅 Intel 旧机型）
- **3 = System（thermalmonitord 系统接管）← 原代码 `$0 != 0` 也把这个算成强制**

Mode 3 下风扇按系统调度运行（非满速），但 `isForced()` 用 `$0 != 0` 返回 true → 复选框打勾 → 与实际情况矛盾。

### 修改内容（3 个文件，3 处核心修复）

1. **FanControl.swift** — `isForced()` / `setFullSpeed()`
   - 新增 `modeKey(_:conn:)`：运行时探测小写 `F%dmd` → 大写 `F%dMd`（M5 用小写 key）
   - `isForced()` 改为 `mode == 1 || mode == 2`，排除 Mode 3
   - `setFullSpeed()` 改用 `modeKey()` 自适应 key 大小写

2. **AppDelegate.swift** — `showSettings()`
   - 添加 `DispatchQueue.main.async`：首次点击时 `settingsWindow` 懒加载创建（含 SMC 连接），此时 NSMenu tracking loop 仍占用事件，直接 `makeKeyAndOrderFront` 会被丢弃

3. **SettingsWindowController.swift** — 风扇区块重构
   - `show()` 恢复 `syncFanSection()`（`isForced()` 修复后安全）
   - `syncFanSection()` 增强：
     - RPM 交叉验证：若 forced 但 actualRPM < maxRPM/3 → 自动取消勾选 + 状态栏提示"系统已接管控制"
     - SMC 不可用时回退 `UserDefaults.bool("fanForceEnabled_N")`
   - `onFanCheckboxChanged`：成功时写 `UserDefaults` + 调 `syncFanSection()` 做 RPM 验证
   - `onReset` / `restoreNextFan`：清除后写 `UserDefaults(false)`
