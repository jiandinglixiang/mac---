# 2026-09-01

## 风扇设置 bug 排查 + 改为 80% 最高转速

排查 `ClipboardHistory/Sources/FanControl.swift` + `SettingsWindowController.swift`，修复 7 处 bug 并落地「勾选后 = 最高转速 80%（不再满速）」。

### 修复的 bug
1. **CLI `set <fan> <rpm>` 的 rpm 被完全忽略**（`setFullSpeed` 内部自己写 `F%dMx`）→ 上层传任何目标转速都无效，80% 需求无法表达。改为 `setTargetRPM(fan, rpm:)`。
2. **危险回退路径**：`if (try? writeKey(mdKey,1)) != nil {...} else { 写 F%dMn = 最大值 }`——用「写入是否成功」判断模式 key 是否存在；在 M3/M4 被固件拒绝(0x82)时会把「建议最低转速」顶到最大值。已删除该回退，改为 Ftst 诊断解锁（见下）。
3. **缺 Ftst 解锁**：M3/M4 在 Mode 3 下写模式位被拒，`Ftst=1` 可抑制 thermalmonitord 回收（等模式脱离 3 后重试写 1，约 3~6s）。仅当直写返回 `keyFailed(_, 0x82)` 且 Ftst 存在时进入，避免权限不足时白等 10s。
4. **模式会被系统回收**（最大体验问题）：thermalmonitord 每 4s（高负载 250ms）轮询回收，一次性 sudo 子进程写完即退出 → 「勾上又自己弹回」。新增 `FanSupervisor`：每 5s 只读模式位（无需 root），仅在被回收时才补发；睡眠停机/唤醒补发；App 启动恢复上次勾选。
5. **RPM 交叉验证误清勾选**：操作后立刻用 `actual < max/3` 判定「系统已接管」并强制置 off，但风扇爬升需要数秒 → 刚勾选就被弹回。改为只提示「加速中」，不再推翻复选框。
6. **sudoers 探针 bug**：`try? probe.run()` 抛异常时 `terminationStatus` 仍是 0 → 误判已免密。改为 `probeSudoSilent()` 显式区分「启动失败」与「退出码 0」。
7. **/tmp 固定名临时文件**（占坑 DoS / 竞态）→ `mkdtemp` 0700 随机目录。

### 关键事实（本机 MacBookPro18,1 = M1 Pro，macOS 26.6.2）
- `--fanctl info` 实测：风扇 0 最大 4296 RPM、风扇 1 最大 4744 RPM，80% = 3437 / 3795 RPM；模式位当前 0（自动）。
- Apple Silicon `F%dTg`/`Mx` 是 flt 小端；模式 key 大小写随代际变（M1~M4 `F%dMd`，M5 `F%dmd`），必须运行时探测；`F%dID` 在 Apple Silicon 读不到（名称显示 `?`，已从输出移除）。
- 非 root 写 `F0Md` 返回 `kern_return=-536870207`（NotPrivileged），0.6s 快速失败，符合预期。
- Ftst 解锁会全局抑制系统热伺服 → 此时未勾选的风扇不会随温度升速，代码里对所有风扇一并设 80% 目标，避免过热。
- 参考：https://github.com/agoodkind/macos-smc-fan （M1~M5 SMC 风扇控制逆向研究，Ftst 解锁与模式 0/1/3 语义）。
